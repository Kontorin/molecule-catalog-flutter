# [ЛР-3] Сеть: Каталог молекул

## Что сделано

Каталог молекул, деталь соединения и экран механизма действия переведены
с моков на ChEMBL API. Управление состоянием осталось на Cubit: он хранит
загрузку, данные и ошибку, не зависит от Dio и DTO.

- Реализована цепочка API-клиент → датасорс → репозиторий → Cubit → экран
  для молекул и механизмов действия.
- Общий экземпляр Dio создаётся в корне приложения; базовый адрес, таймауты
  и отладочный LogInterceptor настроены в `common/network`.
- DTO генерируются через `json_serializable`; `*.g.dart` добавлены в Git.
  Датасорсы переводят сетевые ошибки в `LoadException`, репозитории
  преобразуют DTO в доменные модели через мапперы.
- Список и детали показывают индикатор загрузки, сообщение об ошибке
  и кнопку «Повторить». Деталь загружается отдельным запросом.
- Добавлены серверный поиск по основному названию или точному ChEMBL ID,
  пустой результат поиска и подгрузка страниц по 20 записей без повторов.
  Ошибка следующей страницы сохраняет уже загруженный список.
- Молекула и связанные механизмы загружаются параллельно; названия мишеней
  запрашиваются пакетами. Возврат со страницы до завершения запроса безопасен.
- Моков в `lib/` нет; снимок из ЛР2 перенесён в `docs/reference`
  и не используется приложением. Кэш и сохранение данных на диск не добавлялись.
- В небольшом по высоте окне блок ошибки прокручивается, сохраняя доступ
  к кнопке «Повторить».
- SVG-схемы структур загружаются из ChEMBL: миниатюры в списке и увеличенная
  схема в детали. При отсутствии структуры или ошибке изображения остаётся
  иконка-заглушка, данные молекулы доступны.

Проверка: `flutter analyze`, `flutter build web`, `flutter build windows`
и повторная генерация DTO прошли успешно. В Chrome проверены загрузка списка
и детали, ошибка подключения и восстановление кнопкой «Повторить»,
включая окно 640×300. Скриншоты сделаны в Web-версии.
Для схем проверены узкое окно, тёмная тема, запись без структуры и
недоступный сервер изображений: ошибка картинки не скрывает свойства молекулы.

## Известные проблемы

- Каталог по умолчанию показывает записи с `pref_name`. Точный ChEMBL ID
  позволяет открыть и запись без названия. Поиск по синонимам, русским
  названиям и химической структуре не реализован.
- Механизмы ищутся по ID выбранной записи в полях `molecule_chembl_id`
  и `parent_molecule_chembl_id`. Родитель из иерархии солевой формы отдельно
  не определяется, поэтому его механизмы могут не отображаться.
- Ошибка связанных данных переводит всю деталь в состояние ошибки;
  «Повторить» заново загружает молекулу и связанные записи.
